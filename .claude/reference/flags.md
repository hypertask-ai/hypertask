# Flag-release detail

Read AGENTS.md Feature flags and verify-qa Released flags for defaults, exceptions, cleanup, premerge recording and emergency flag-off.

New feature and improvement flags set `defaultMode: "EVERYONE"` in their definition file, so the change is live at once and can still be switched off in seconds (Valentin, 2026-10-20, HTPR-7389: "we set it to live right away for everyone by default unless there is a REAL STRONG reason not to"). Exceptions are `kind: "internal"` and a flag whose `releaseRisk.highRisk` names one of four high-risk kinds: `money`, `access` (login and access), `data-deletion` or `customer-email`. High-risk flags set `defaultMode: "OWNER_AND_QA"` and get a Fable review plus one HT Product Lead check before anyone asks Valentin to release them. When unsure whether a ticket is high risk, ask Fable and HT Product Lead. Existing flags keep their current mode. Switching an existing flag still needs his thumbs up (Switching flags in /ship).

Only for Valentin's own explicit request, a new flag may instead use `defaultMode: "OWNER_ONLY"` with `releaseRisk.ownerRequest: { quote: "<his exact request>", ticketUrl: "<ticket link>" }`: the quote must be non-blank and the link must match `^https://app\.hypertask\.ai/detail/project-\d+/\d+$`. This exception permits only Owner only, not Owner + QA or Off, and does not replace required `releaseRisk.highRisk` metadata.

Only saved-data, security and crash fixes skip the flag. Legal, privacy, compliance and urgent work still get one; urgent or explicitly requested work may go to Everyone at once through a `Question: Switch <flag-key> to Everyone?` thumbs up, keeping `kind` honest (AGENTS.md, Feature flags; YPER4-418, YPER4-419). `feature-flag-gate` fails a `[BUGFIX]` or `[INFRA]` PR that shows existing UI in new places or to more users without a ticket flag.

New or changed visible UI needs Valentin's yes on a clickable wireframe on its ticket before code: load `wireframe`, then move to **UX Sign-off** (board 15 column 22502); the `ux-signoff` status enforces this. A `[BUGFIX]` restoring intended behaviour is exempt from wireframe sign-off, but every new component file needs his yes naming it (Valentin, 2026-10-10).

# Ticket account switch

With one signed-in account, `/detail/project-{id}/1` stays the open address. `POST /api/auth/ticket-account-switch` answers JSON containing `action` and no ticket title. A cross-origin post answers `{ action: "stay" }` before any account read, the same trusted-origin check other sensitive POST routes use. With `htpr-9621-auto-switch-account` on, default mode OWNER_AND_QA, the route first proves another account on this device has a server-side session, then asks whether that account can open the ticket. A missing ticket and a ticket no verified sibling can open both answer `{ action: "stay" }` after the same reads. One match switches that session, forwards `ht_session` and `nookies_user`, and the page toasts the account name. Other tabs reload onto that account. Several return with a mark that opens the existing account switcher, and the pick stays on the ticket and toasts the account. Prefixed keys such as `/detail/project-15/HT-9621` and renamed numbers resolve the same way as the detail page. The reply carries no title, email, account id, or session token. Repeated probes, a rate-limit outage, and a session or ticket lookup outage stay on the ticket; the per-ticket attempt guard expires after five minutes so a later visit probes again. The flag off leaves today's page and mounts no probe, so no storage key and no cross-tab listener appear. A visit marked by a finished switch still toasts the account and reloads the other tabs, even when the destination account is outside the flag audience. Do not change the flag audience. The server route is `src/app/api/auth/ticket-account-switch/route.ts`. The switcher is `src/components/Modals/commands/SwitchAccount/SwitchAccountModal.tsx`. Closest proof is `tests/htpr-9621-auto-switch-account.test.cjs`.

# E2E verification fleet

> Hand-maintained page (not auto-generated by OpenWiki — it documents a harness that lives outside this repo). Do not delete on refresh.

Status as of 2026-08-07. Tracking ticket: https://app.hypertask.ai/detail/project-15/4985

LLM agents drive a real browser through user flows against production and judge the result from screenshots. Each flow runs in its own E2B cloud sandbox. It exists because nobody manually QAs the app after every merge.

## How a flow runs

1. Orchestrator creates a throwaway board `verify-<runId>-<flow>` owned by the test account and seeds it through the API.
2. It spawns an E2B sandbox (**`desktop` template** — the base template crashes Chromium) and injects session cookies.
3. `openai/gpt-5.6-luna` at `xhigh` drives Playwright step by step from screenshots + a DOM summary, max 25 steps.
4. A judge model reviews screenshots and the action log and issues pass/fail.
5. Cleanup deletes the board in a `finally`. A hard kill skips it, leaving stray boards — `findThrowawayBoards`/`cleanupThrowawayBoards` in `app-fixtures.mjs` clean up.

## Auth (logged-in suite)

Dedicated production account `verification-fleet@crolab.org`, **userId 1248**. Never Valentin's account.

Login is headless: the orchestrator pulls `JWT_SECRET`/`JWT_ISSUER`/`JWT_AUDIENCE` from the Vercel API (project `hypertasks-prod`) at runtime, mints a short-lived `email-link` JWT, POSTs it to `/api/auth/verify-email-token`, and injects only the resulting `nookies_user` + `ht_session` cookies into the sandbox browser.

**The signing secret never enters a sandbox or a tracked file.** Runtime tripwires enforce this; keep it that way.

## Constraints that bite

- **Free plan = 3 boards.** Each in-flight flow holds one throwaway board, so app-suite concurrency is capped at 3 (`APP_SUITE_CONCURRENCY` in `config.mjs`). Higher concurrency returns `HTTP 403: Free plan includes 3 boards`. The account's default `MyBoard` was deleted to free the third slot; the app does not recreate it.
- **Hypertask is keyboard-first.** Most actions (rename board, add column, archive, filters) exist only in the Ctrl+K command center, not in settings pages. Agents that hunt for buttons burn all 25 steps and fail. Flow prompts must name the command-center path.
- **DeepSeek v4 flash cannot be used.** It is text-only on OpenRouter; every call returns `404 No endpoints found that support image input`. Any driver/judge swap must be vision-capable.

- Demo suite: 34/50 pass.
- App suite: 15/25 pass, **but** deterministic triage (`triage.mjs`, no LLM) showed 9 of the 10 failures were the agent driving badly, not product defects. Real pass rate for the product is higher than the raw number.

## Rules for anyone running this

- **Triage before filing.** LLM verdicts are not evidence. Re-run the failing action deterministically (see `triage.mjs`) and confirm at the data level. Several confident-looking failures turned out to be the agent's fault, a stale API read, or a cookie banner swallowing a keypress.
- **No cron yet.** Nightly scheduling waits until the harness fails only for real reasons; a daily report of 10 false reds trains everyone to ignore it.
- **Never point the fleet at a real user's account or board.** Flows must stay on their own throwaway board.
